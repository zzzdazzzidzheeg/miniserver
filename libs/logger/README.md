# Logger

Простой логгер для серверного приложения. Он пишет сообщения в консоль и, при необходимости, дополнительно сохраняет их в файл.

## Назначение

Логгер используется для:

- отслеживания состояния сервера;
- вывода диагностической информации во время разработки;
- записи предупреждений и ошибок в файл;
- фильтрации сообщений по уровню важности.

## Уровни логирования

Логгер поддерживает четыре уровня:

- `Debug` — подробная отладочная информация;
- `Info` — обычные информационные сообщения;
- `Warning` — предупреждения, которые не останавливают работу;
- `Error` — критические ошибки.

Порядок важности следующий:

`Debug < Info < Warning < Error`

## Основной API

### Класс `Logger`

```cpp
#include "logger.h"

Logger::setLogLevel(LogLevel::Info);
Logger::setLogFile("logs/server.log");

Logger::debug("Подробная диагностика");
Logger::info("Сервер запущен");
Logger::warning("Подключение к внешнему сервису медленное");
Logger::error("Не удалось открыть соединение");
```

Методы класса:

- `setLogLevel(LogLevel level)` — устанавливает минимальный уровень логирования;
- `setLogFile(const std::string& filename)` — включает запись в указанный файл;
- `debug(...)`, `info(...)`, `warning(...)`, `error(...)` — логирование сообщений;
- `clear()` — очищает текущий лог-файл и записывает сообщение о сбросе.

### Функции-обёртки

Также доступны функции в стиле C:

```cpp
log_set_level(LogLevel::Warning);
log_set_file("logs/app.log");
log_info("Запуск приложения");
log_warning("Некорректный запрос");
log_error("Ошибка обработки");
```

Доступны следующие функции:

- `log_set_level(...)`
- `log_set_file(...)`
- `log_clear()`
- `log_debug(...)`
- `log_info(...)`
- `log_warning(...)`
- `log_error(...)`

## Поведение логгера

### Вывод в консоль

Каждое сообщение всегда выводится в стандартный вывод (`std::cout`) в формате:

```text
[YYYY-MM-DD HH:MM:SS] [LEVEL] message
```

Пример:

```text
[2026-10-03 12:30:45] [INFO] Сервер запущен
```

### Вывод в файл

Если вызван `setLogFile(...)` или `log_set_file(...)`, логгер открывает файл в режиме добавления (`std::ios::app`).

Это означает, что новые записи дописываются в конец файла, а не перезаписывают его.

### Фильтрация

Если установлен уровень, например `Info`, то сообщения уровня `Debug` не будут записываться.

Пример:

```cpp
Logger::setLogLevel(LogLevel::Warning);
Logger::info("Этот текст не будет показан");
Logger::warning("Этот текст попадёт в лог");
```

## Очистка файла

Метод `clear()` очищает текущий файл логов и затем записывает сообщение:

```text
[YYYY-MM-DD HH:MM:SS] [INFO] Logger: Log file cleared
```

## Ограничения и замечания

- По умолчанию минимальный уровень — `Debug`.
- Если файл не задан, логирование идёт только в консоль.
- Логгер потокобезопасен: записи защищены мьютексом.
- Время в сообщении формируется локальным временем системы.

## Пример инициализации

```cpp
#include "logger.h"

int main() {
    Logger::setLogLevel(LogLevel::Info);
    Logger::setLogFile("server.log");

    Logger::info("Сервер стартовал");
    Logger::warning("Проверка входящих соединений");
    Logger::error("Не удалось подключиться к базе данных");

    return 0;
}
```

## Рекомендации

- Для разработки используйте `Debug` или `Info`.
- Для production-среды лучше использовать `Info` или `Warning`.
- Для критических сценариев оставляйте `Error` и `Warning` в логах.

Этот логгер подходит для небольших серверных приложений, где важны простота, минимальный объём кода и возможность быстро включить запись в файл.
